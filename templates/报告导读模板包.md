# 报告导读模板包

从 `chapter-content-generator` skill 的 T1-T19 模板中,挑出 5 个适配「报告解读」场景的轻量版。

**核心理念**:不是把读者教成专家,而是让读者先有「体感」再进「数据」,最后带走「洞察」。
**与 skill 的关系**:skill 面向教材章节改造(T1-T19 + 策略包 + 26 项检查),本包只取 5 个思路,降低认知负荷,不直接套用。

---

## 模板一览

| 编号 | 名称 | 来源 | 放在哪 | 解决什么问题 |
|:---:|:---|:---:|:---|:---|
| RG-1 | 经验激活 | T1 类比设计 | 导读开头 | 读者对报告主题没直觉 → 先用真实数据画面建立体感 |
| RG-2 | 概念对比卡 | T2 概念对比表 | 概念首次出现处 | 报告引入新概念,读者容易混 → 一张表看清差异 |
| RG-3 | 方法流程图 | T9 操作流程图 | 方法介绍段 | 报告方法链太抽象 → 可视化降低理解门槛 |
| RG-4 | 易混淆警告框 | T16 易混淆对 | 数据密集处 | 读者容易误读某个数据 → 显式提醒「别踩这个坑」 |
| RG-5 | 镜像反思(Think-Aloud) | T6 Think-Aloud | 镜像区 | 教育者不知道怎么「读报告」 → 示范读到数据时怎么想 |

## RG-1 · 经验激活

**来源**:T1 类比设计(日常经验激活)
**放在哪**:导读开头,正文之前
**解决什么**:读者对报告主题没有直觉 → 先用 2-3 个真实数据场景建立体感

### 模板

```markdown
### 导读 · [一句话主题]

在翻到报告原文之前,先给你 [N] 个画面,都是 [数据来源] 里长出来的:

[场景 1]:[具体时间/数字/画面描述]——[一句话解读]。

[场景 2]:[具体时间/数字/画面描述]——[一句话解读]。

[场景 3]:[具体时间/数字/画面描述]——[一句话解读]。

这 [N] 个画面告诉我们:**[一句话洞察]**。
```

### 示例(上篇·用法)

```markdown
### 导读 · AI 跟着钟表走,成本跟着价值走

在翻到报告原文之前,先给你三个画面,都是 Claude 真实用法数据里长出来的:

凌晨 5 点,天还没亮,一个人醒来睡不着,拿起手机问 AI:「怎么才能睡个整
觉?」——睡眠建议的请求量,在黎明前几个小时达到全天峰值。

傍晚 6 点,下班回家路上,另一个人在地铁上问:「今晚做什么菜好?」——食谱
请求在傍晚 6 点是全天平均水平的 2.3 倍。

4 月 14 日,美国报税截止日前一天,报税相关请求量飙升——是 5 月平均日的
8 倍。第二天还保持同样高。4 月 16 日,骤降。

这三个画面告诉我们:**AI 用法不是飘在云端的,它精准刻着外部世界的节律。**
```

### 检查

- [ ] 2-3 个场景,都有具体数字(时间/倍数/百分比)
- [ ] 场景来自报告真实数据,不编造
- [ ] 每个场景 = 「谁在什么时刻做了什么」,有画面感
- [ ] 一句话洞察收尾,与后续正文形成「体感 → 数据」的递进
- [ ] 场景之间是并列关系,不是递进(各自独立说明主题)

## RG-2 · 概念对比卡

**来源**:T2 概念对比表
**放在哪**:概念首次出现处(通常在导读或正文第一段)
**解决什么**:报告引入新概念,读者容易混 → 一张表看清差异

### 模板

```markdown
#### [概念 A] vs [概念 B]:一张表看懂

| | [概念 A] | [概念 B] |
|---|---|---|
| **英文** | [A 英文] | [B 英文] |
| **是什么** | [一句话定义] | [一句话定义] |
| **怎么算的** | [计算方法/数据来源] | [计算方法/数据来源] |
| **关键特征** | [1-2 个] | [1-2 个] |
| **常见误区** | [读者容易怎么理解错] | [读者容易怎么理解错] |

**一句话区分**:[A 和 B 的本质差异是什么]。
```

### 示例(上篇·自动化 vs 增强)

```markdown
#### 自动化 vs 增强:一张表看懂

| | 自动化(Automation) | 增强(Augmentation) |
|---|---|---|
| **是什么** | 人把整个任务交给 AI,自己最少输入 | 人和 AI 来回对话,一起打磨产出 |
| **对应模式** | 指令式、反馈循环式 | 任务迭代式、学习式、验证式 |
| **典型对话** | 「翻译这份文档」→ 拿走结果 | 「帮我改这段……再随意一点」→ 来回几轮 |
| **关键特征** | 人少输入,AI 独立决策多 | 人多参与,AI 辅助判断 |

**一句话区分**:自动化是「交给它」,增强是「一起干」。
```

### 检查

- [ ] 两个概念在报告中确实被对比过(不是自己编的对立面)
- [ ] 「怎么算的」一栏有具体说明,不是抽象定义
- [ ] 「常见误区」一栏写出读者最容易怎么理解错
- [ ] 一句话区分能让人看完就记住核心差异
- [ ] 表格在手机上能正常显示(列不超 5 个,文字不超长)

## RG-3 · 方法流程图

**来源**:T9 操作流程图
**放在哪**:方法介绍段,或系列总序里介绍「这份报告做了什么」的地方
**解决什么**:报告方法链太抽象 → 可视化降低理解门槛

### 模板

```text
[步骤 1:输入/数据源]
        │
        ▼
[步骤 2:处理/分类]
        │
        ▼
[步骤 3:输出/发现]
```

**核心要点**:
1. [步骤 1 的一句话解释]
2. [步骤 2 的一句话解释]
3. [步骤 3 的一句话解释]

**为什么重要**:[这个方法设计让报告能做到以前做不到的什么事]。
```

### 示例(本系列方法链)

```text
   小时级采样(每小时请求数据)
        │
        ▼
   Artifact 分类器(30+ 产出类别)
        │
        ▼
   问卷关联用法(9,700 人 + 真实 session)
        │
        ▼
   三章发现(节奏 / 产出 / 感知)
```

**核心要点**:
1. 小时级采样——过去只采 7 天,看不到日内波动;现在每小时采样,捕捉到凌晨 5 点的睡眠请求
2. Artifact 分类器——过去只知道「用了多少 token」,不知道「用出了什么」;现在每次对话产出被打标签
3. 问卷关联用法——过去只问「你觉得用 AI 多吗」;现在是「我们看到了你实际用了多少,再问你觉得如何」

**为什么重要**:三个升级合在一起,第一次让「AI 嵌入工作」从模糊叙述变成可观测的实证图景。
```

### 检查

- [ ] 流程图用 ```text 代码块,手机上能完整显示(宽度 ≤ 40 字符)
- [ ] 步骤不超过 5 个,超过就拆成子流程
- [ ] 每个步骤 = 一句话,能独立看懂
- [ ] 「核心要点」给每个步骤补一句解释
- [ ] 「为什么重要」说明这个方法设计带来的认知增量

## RG-4 · 易混淆警告框

**来源**:T16 易混淆对警告框
**放在哪**:数据密集处,或结论可能被误读的地方
**解决什么**:读者容易误读某个数据 → 显式提醒「别踩这个坑」

### 模板

```markdown
> <img src="[warning-icon]" width="18" height="18" alt="注意" style="vertical-align: middle;"> **读到这里,注意别踩这个坑**
>
> [容易混的两件事]:[一句话澄清]
>
> —— 出自报告第 [X] 章 / 脚注 [N]
```

(如果没有 SVG 图标,用 ⚠️ 替代也行)

### 示例(下篇·感知)

```markdown
> ⚠️ **读到这里,注意别踩这个坑**
>
> **10% 自我失业预期 ≠ 实际失业率 10%**:10% 是受访者「评估自己明年可能失业为可能或很可能」的份额,而美国年化实际离职率约 13.4%。受访者是偏向稳定就业的知识工作者,基线离职风险低于平均,所以 10% 仍可能意味着感知风险升高。
>
> —— 出自报告第 3 章 / 脚注 23
```

### 检查

- [ ] 混淆的两件事在报告中确实容易被混为一谈
- [ ] 澄清用一句话能说清,不绕弯
- [ ] 注明出处(章节 + 脚注号),方便读者回查
- [ ] 不改变报告结论,只是防止误读
- [ ] 用 `>` 引用块 + 图标,视觉上与正文区分

## RG-5 · 镜像反思(Think-Aloud)

**来源**:T6 Think-Aloud
**放在哪**:镜像区(每篇末尾)
**解决什么**:教育者不知道怎么「读报告」 → 示范读到数据时怎么想

### 模板

```markdown
## 🪞 镜像 · 教育者该怎么读「[本章主题]」

读完这一章,我脑子里一直在转 [N] 个问题:

**第一个**:[问题]?

报告给了一个数据:[具体数据点]。这个数字的意思是 [解释]。
但更值得注意的是 [报告给的反直觉发现/洞察]。

**这不是说 [预防误读/避免极端]**。报告自己也反复强调 [caveats]。

但报告也给了一个 [正面/温暖的结尾]:[结尾数据或结论]。

**[一句话总结教育启示]**。
```

### 示例(下篇·感知)

```markdown
## 🪞 镜像 · 教育者该怎么读「感知」

读完这一章,我脑子里一直在转一个问题:**我们的学生,正在害怕一份他
们还没挣到的工作。**

10% 的受访者认为自己明年可能失业——这个数字略低于美国年化离职率
(13.4%)。但超过 1/3 的人说初级同事失业概率 >60%。

**焦虑是朝外的,朝着更年轻、更初级的人。**

而我们的学生,恰恰站在「初级」那一端。他们还没开始工作,就已经在担心
工作被 AI 抢走。这种担心,有多少是基于真实数据,有多少是基于恐惧的
投射?

报告给了一个反直觉的答案:**用得越深,越乐观。**

这不是说 AI 没有风险。报告自己也反复强调样本偏差、自我评估不排除技能
萎缩、分箱回答使斜率偏零。这些 caveat 都在脚注里,建议仔细读。

但报告也给了一个温暖的结尾:当被问到「十年后你希望 AI 塑造的经济什
么样」,Top 3 主题是协作(>50%)、苦差自动化(>50%)、共享繁荣(约
1/3)。

**不是替代,不是乌托邦,是协作 + 自动化苦差 + 收益共享。**
```

### 检查

- [ ] 以第一人称「我」写,展示思考过程,不是总结报告
- [ ] 有具体数据点引用,不是泛泛而谈
- [ ] 包含「预防误读」——说明 caveats,不走向极端
- [ ] 与教育实践有连接(对学生/课程/教学的启发)
- [ ] 一句话总结收尾,能让人带走
- [ ] 语气中立,不评判(不说「报告做对了/做错了」)

## 组合建议

不同位置推荐的模板组合:

| 位置 | 推荐组合 | 说明 |
|---|---|---|
| 上篇导读 | RG-1(经验激活) + RG-2(概念对比卡) | 先用画面建立体感,再用对比卡理清核心概念 |
| 下篇导读 | RG-1(经验激活) + RG-4(易混淆警告框) | 先用反直觉数据吸引注意,再提醒常见误读 |
| 镜像反思 | RG-5(Think-Aloud) + RG-4(易混淆警告框) | 先示范思考过程,再提醒 caveats |
| 系列总序 | RG-3(方法流程图) | 介绍报告方法链,降低理解门槛 |
| 正文中间 | RG-2(概念对比卡) | 新概念首次出现时,用卡片澄清 |

## 质量检查清单(轻量版)

### 整体检查

- [ ] 导读/镜像与正文形成「体感 → 数据 → 洞察」的递进
- [ ] 镜像与导读呼应(导读建立体感,镜像带走洞察)
- [ ] 没有「做对了/做错了」等评判语气
- [ ] 所有数字有出处(报告正文或脚注)

### 模板专项检查

- [ ] RG-1:场景来自真实数据,有画面感
- [ ] RG-2:对比的概念在报告中确实被对比过
- [ ] RG-3:流程图在手机上能完整显示
- [ ] RG-4:混淆的两件事确实容易被混为一谈
- [ ] RG-5:以第一人称写,展示思考过程
